OpenWrt Flow Offload + PBR Wrong-MAC Mitigation

A selective firewall4 include and diagnostic testbed that fixes Layer-2 destination MAC misdelivery for policy-routed and NATted traffic when software or hardware flow offloading is enabled in OpenWrt 24.10.

⚡ Quick Install (v0.1.4) 📦 Download .ipk GitHub Repository

⚡ Quick Installation

Choose your preferred installation method on your OpenWrt router:

Add the community feed to your router's opkg configuration to install and receive automatic updates:

echo 'src/gz flowoffloadpbr https://bomberrie.github.io/openwrt-flowoffload-pbr-mac-misroute/ipk' >> /etc/opkg/customfeeds.conf
opkg update
opkg install openwrt-flowoffload-pbr-mitigation

✓ Installs /etc/nftables.d/99-flowoffload-pbr.nft and reloads firewall4 immediately.

Apply the hotfix directly from your workstation to the router via SSH:

ssh root@router 'sh -s' < mitigation/apply.sh

To revert and rollback the hotfix at any time:

ssh root@router 'sh -s' < mitigation/rollback.sh

Download the standalone package and install it with opkg:

wget -O /tmp/openwrt-flowoffload-pbr-mitigation_0.1.4_all.ipk \
  https://github.com/bomberrie/openwrt-flowoffload-pbr-mac-misroute/releases/download/v0.1.4/openwrt-flowoffload-pbr-mitigation_0.1.4_all.ipk
opkg install /tmp/openwrt-flowoffload-pbr-mitigation_0.1.4_all.ipk

Create the drop-in include manually in /etc/nftables.d/ and restart the firewall:

cat <<'EOF' > /etc/nftables.d/99-flowoffload-pbr.nft
table inet fw4 {
  chain ft {
    meta mark != 0 counter return
    ct status { dnat, snat } counter return
  }
}
EOF
/etc/init.d/firewall reload

🔍 The Routing & Flowtable Bug Explained

In OpenWrt 24.10, combining software or hardware flow offloading (e.g. MediaTek MT7621 PPE) with Policy-Based Routing (PBR) and NAT leads to a Layer-2 misrouting defect. Return packets destined for a LAN client are transmitted onto the LAN with the Ethernet destination MAC of the PBR next-hop / VPN gateway instead of the LAN client's MAC.

❌ Without Mitigation (Buggy Flow)
  • Client (10.0.0.2) sends UDP DNS query.
  • PBR tags packet with fwmark 0xff & routes via VPN gateway.
  • Flowtable fast-path accelerates the flow & caches early neighbor info.
  • WAN/VPN reply arrives; fast-path reuses the cached VPN gateway L2 neighbor.
  • Packet sent to LAN with VPN Gateway's MAC: LAN client drops it silently.
✅ With Mitigation (Selective Bypass)
  • Client sends UDP DNS query with PBR mark.
  • Guard catches meta mark != 0 & ct status { dnat, snat }.
  • Early return skips the flow offload @ft fast-path.
  • Flow remains in kernel slow path: routing & ARP/ND evaluated per-packet.
  • Packet sent to LAN with Client's true MAC: Connection succeeds flawlessly.

Performance Impact: Isolated strictly to policy-routed and NATted flows. Bulk unmarked LAN ↔ WAN throughput continues to utilize full hardware/software flow offloading acceleration at wire speed.

🧪 Network Namespace Reproducer Lab

The repository includes a self-contained 4-namespace Linux routing lab (ns_client, ns_router, ns_vpngw, ns_wan) that reproduces the topology and validates Layer-2 packet delivery on any Linux host with nftables: 

# Run lab with flow offload on and mitigation enabled:
sudo ./reproducer/netns-lab.sh run

# Run lab with mitigation disabled to observe reproduction:
sudo FLOW_OFFLOAD=1 MITIGATION=0 ./reproducer/netns-lab.sh run

# Execute automated CI smoke test:
make smoke

# Tear down namespaces & clean logs:
make clean

🩺 Router Diagnostic Collector

Gather routing tables, nftables rulesets, flowtable dumps, conntrack logs, and synchronized LAN/WAN PCAPs directly on OpenWrt:

# Run collector on target router:
./diagnostics/collect.sh

# Outputs collected into:
/tmp/offload-pbr-diag/

📋 Manual Router Triage Commands

Inspect active flowtable state:

nft list flowtables
nft list flowtable inet filter ftoffload

Monitor neighbor (ARP/ND) churn:

ip -s neigh show

Verify LAN L2 destination MAC:

tcpdump -nn -e -i br-lan udp port 53

Live packet path trace:

nft monitor trace
